## 〇、一声许愿

10 月 17 日，DeepSeek 把 V4.1 Flash 更新到 1017 版，公告标题写得很有画面感：**许愿式编程一键成真**。网页端、APP 与 API 同步切到新模型，权重照旧开源，Hugging Face 与 ModelScope 都能下。

同一则公告里还有几条容易被标题盖住的信息：

- 模型针对 DeepSeek Harness、腾讯 CodeBuddy、WorkBuddy 几个框架做了专门优化，并要求 Harness 升到 0.2.1-rc.1 以上才能拿到最优体验；
- 自研搜索引擎的 Search / Fetch 接口对外开放，5 元/千次，11 月 1 日零点之前在上述 agent 框架里调用不计费；
- 以及一句技术上的定性——这是一次「性能-费用的帕累托改进」。

帕累托改进是个很重的说法。它的意思不是「更强」，也不是「更便宜」，而是**没有任何一项变差的前提下，有一项变好**。厂商敢用这个词，等于宣称自己在价格-能力平面上把整条曲线往左推了一格。

这句话如果成立，之前所有关于「AI 让人更忙」的讨论，都得重新对一遍口径。

分界线整齐得可怕。

它赢的地方：在既有仓库里把 issue 改对（DeepSWE 77.0 对 74.0）、把自动化流程跑通（60.5 对 50.3）、多步工具调用、带工具的图表与视觉问答。这些任务的共同点是**验收标准可以先于工作存在**——有测试、有脚本、有参考答案，跑绿了就是对了。

它输的地方：HLE 42.6 对 56.3（跨学科硬知识）、Terminal-Bench 42.3 对 51.8（长链条命令行）、ProgramBench 29.1 对 37.0（从零写程序）、NL2Repo 68.2 对 75.3（一句话到一个完整仓库）。这些任务的共同点是**你得自己判断什么算完成**，而且中途没有红灯可等。

一句话：**能测的那一半它赢了，得靠人定的那一半它还输着。**

成本坐标更刺眼。官方那张图上（横轴对数、纵轴 Pass@1），77.0 分落在每任务一元出头；Claude Opus 5 的同一指标落在五十元上下，Claude Fable 5 落在百元开外。差距不是百分之几十，是四十倍量级。

四十倍的钱买到的不是更高的分——DeepSWE 上 Opus 5 反而低 3 分——而是另一些东西：HLE 高 13.7、Terminal-Bench 高 9.5、NL2Repo 高 7.1。**贵的模型在为「没有测试可跑」的地方收费。**

## 二、够用线在 Opus 4.8，不在最高分

社区里有个说法，比任何榜单都实在：只要模型能到 Claude Opus 4.8 那一档，用起来就不那么痛苦了——不是惊艳，是**不别扭**：知道该看哪些文件，改完会自己跑一遍，报错不会原地打转，也不至于把整个仓库推倒重来。

这条线不是能力上限，是体感阈值。

而这次公告把对手栏直接写成了 Opus 5。这个动作的潜台词是：它自认已经越过那条线，开始往上够一档。

越过之后，事情的性质变了。**能力从「卖点」变成「入场券」。** 入场券只能按入场券的价格卖——这也是为什么「对标 Opus 5」这件事本身在贬值：当 77 分和更高分的体感差别只剩在少数场景里，多出来的分只能卖给那些真能分辨的人。

一个反直觉的推论：**能力过剩最先挤压的不是低端模型，是高端模型的溢价。** 低端还能靠便宜活着，高端必须证明多出来的那一截值那个价——而在标准工程上，这一截越来越难证明。

## 三、「工程」是个滑词

9-16 那篇写过一句话：代码没你想得难，工程没你想得简单。它举了三起事故——Knight Capital 的一个 flag 唤醒死代码，45 分钟亏掉 4.4 亿美元；S3 的一条 typo 删掉一片服务器；CrowdStrike 的一段配置让 850 万台 Windows 蓝屏。三起事故加起来不到 50 行「代码」，账单是半个互联网加一家上市公司。

现在回头看，那三起事故没有一起是「按规格实现失败」。它们全是规格之外的东西没管住：死代码清理、发布校验、权限隔离、灰度与爆炸半径。

所以「工程」这个词至少指三件事：

- **层一，写**：语法、样板、接口对接、补边界。这一层的门槛在 2022 年就开始塌了。
- **层二，标准工程**：有明确 issue、有隐藏测试、单仓内可闭环的改动——修 bug、迁移、升级依赖、补测试、跨语言重写。这一层正在被 Flash 打塌，DeepSWE 77.0 就是它的标尺。
- **层三，非标准工程**：判据谁定、耦合谁看、爆炸半径多大、出事谁签。这一层没塌，反而更贵。

9-16 那篇说的是层三，这一篇说的是层二。两个「工程」不是一个东西。把它们混着讲，就会得出「AI 既让工程变简单又让工程变难」这种听起来很辩证、其实什么都没说的话。

至于「前 AI 时代写代码是体力活」这个说法，对一半。一个功能的大部分工时确实消耗在实现上：写、接线、补边界、调试、再调试。这部分是可标准化的体力活，也是今天最先被买走的部分。但它同时承担了另一个功能——**它是理解系统的方式**。你把一个模块写一遍，才知道它的边界在哪里、坑埋在哪里。这一步被跳过之后，代价不会出现在交付上，会出现在三年后的排障上。

## 四、便宜改变的不是账单，是做法

算一笔小账。

一次改动带 5 万 token 的仓库上下文，按上一版 Flash 的 \$0.15/百万 token 算，输入成本 0.75 美分；输出 5,000 token，按 \$0.60 算，0.3 美分。合计一美分出头。1017 版还额外压缩了输出长度和任务用时——公告里的第二条卖点就是这个。

生成十个候选补丁，不到 0.1 美元。一个人审一个补丁二十分钟，按一百元一小时算，三十三元。

**候选的边际成本趋近于零，审阅的边际成本一动不动。** 这个不对称会直接改写理性策略：从「想清楚再写对」，变成「多生成、快筛、留证据」。写得对不对不再是第一道关，筛得准不准才是。

钱不会省下来，它会搬家。搬到测试、CI、静态检查、回放、灰度、可观测性、变更审计——这些设施一个都没降价，而且因为候选变多，用量还要涨。**省下来的生成费，会以更高的验证设施投入回流到账上。**

搜索那一栏更值得单独看。公告的同一天，一份对比把各家检索 API 的价格摊开了（按 1 美元 ≈ 6.8 元折算）：

| 服务 | 每 1000 次 | 单次 | 计费口径 | 正文 |
| --- | --- | --- | --- | --- |
| DeepSeek Search | ¥5.00 | ¥0.005 | 成功且有结果才收 | 带正文，不另收 |
| DeepSeek Fetch | ¥5.00 | ¥0.005 | 成功拿到正文才收 | 返回 Markdown 正文 |
| Serper（Google SERP） | ¥2.04–6.80（\$0.30 大包 – \$1.00 入口） | ¥0.002–0.007 | 按次收 | 只有标题与摘要 |
| Exa instant | ¥27.20（\$4） | ¥0.027 | 按次收，含前 10 条 | 正文另算，\$1/1000 页 |
| Brave Search API | ¥34.00（\$5） | ¥0.034 | 按次收 | 结果附上下文 |
| Exa fast / auto | ¥47.60（\$7） | ¥0.048 | 按次收 | 同上 |
| Tavily | ¥54.40（\$8，基础版） | ¥0.054 | 按次收，高级版 \$16 | 可选正文 |

单看「搜索一次」，DeepSeek 不是最便宜的：Serper 的大包价只要它的四成。但那是最大采购包的价——入口价 \$1.00 折合 ¥6.8，反而比 DeepSeek 贵，而且 Serper 不返回正文，正文要另找服务抓。**把「搜到」和「读到」合并算，¥5 这一档反超了**：哪怕只为一半结果抓正文，成本也过了 ¥5。

官方指南把计费口径写得很死：**只有返回 HTTP 200 且产生结果的请求才计费**——Search 的 `results` 必须非空，Fetch 必须返回正文；请求失败、搜索无结果、超时，都不计费。`count` 只改条数不改价格，`need_content` 也不另收。一次调用最多取 50 条，正文自带还同价，单次请求的信息密度可以堆得相当高。

这一条会直接改写 agent 的行为。搜索次数和模型能力是负相关的——心里没底的模型会多搜：同一个问题，强模型搜三次就够，弱模型要搜十几次。过去按调用计费，等于对「能力不足」额外征税：账单差四倍，能力差被价格放大。现在按结果计费、正文自带、失败的尝试免费，这笔税被抹平了。

一句话：**按调用计费鼓励节省，按结果计费鼓励试错。计费口径一变，最优策略就变。**

限制也在那儿：两个接口各 5 QPS，按目标域名另有限速。单个 agent 够用，批量抓取不够——便宜的是调用，贵的是吞吐。这是层三的老规律，换了张脸又来一次。

顺带一提，检索管线里最脏的那一段——抓取、解析、去重、限速、失败重试、正文抽取——被压成了一个 API 调用。**工程里最麻烦的那一截，被做成了默认选项。** 这也是「标准工程被买走」的一部分，只不过这次买走的不是代码，是数据侧的管道。

## 五、许愿攻下的是哪块地

「许愿式编程」这个词很准，也很狡猾。

准的地方在于它描述了对的地方：一句话进去，一个可运行的东西出来。DeepSeek 给的四个案例——故宫 3D 建模、网页版赛车、Godot 复刻《传送门 2》、用 3D 场景演一遍史前到现代——都是这种形状。

狡猾的地方在于它只展示了许愿成功的那一格。这四个案例有个共同的品类特征：**视觉可演示、无真实用户、无数据一致性要求、失败成本为零**。它们的验收标准是「看起来像」，不是「用起来对」。而「看起来像」恰好可以被外部观察者在一分钟内判定——所以演示极有说服力，也极容易高估。

表里的两行把这件事说清楚了：NL2Repo 68.2 对 75.3（一句话到一个完整仓库），ProgramBench 29.1 对 37.0（从零写程序）。**从零项目这一格，它涨得最快，但还没赢。**

10-07 那篇写过同一个形状的现场：一个开源组织一周放出七个 Rust 重造的 Adobe 套件，全部可安装，同一天一位从业者拿真实项目实测，结论是「literally nothing works」。第一英里塌了，第二英里没塌。许愿式编程攻下的正是第一英里——而第一英里恰好是最适合拍成 GIF 的那一段。

所以「一键成真」成立的范围要写清楚：**从零搭一个能演示的东西，成立；从零搭一个要维护十年的东西，还不成立。** 这两件事在 demo 里长得一样，在三年后长得完全不一样。

## 六、没塌的一半

如果标准工程真的被买走了，工程总成本应该下降。但 2025 年 DORA 的报告给了相反的数：90% 的 AI 采用率下，bug 增加 9%，代码审查时间延长 91%，PR 规模增大 154%。

审查时间为什么涨？不是工程师变笨了，是候选变多了、单个 PR 变大了，而「这个改动会不会炸」这个问题，没有任何测试能替你回答。

同一份材料里还有一条更细的：agentic 补丁审查系统 Sashiko 能独立找出 53.6% 后来被人修掉的 bug，这个数字很漂亮；但它的假阳性率在 20% 左右，每五条告警有一条根本不存在。

把这两条放在一起，层三的轮廓就出来了。它由三件不可外包的事构成：

- **判据**：什么算对。测试只能验证你已经想到的约束，想不到的那部分要人来定。
- **耦合**：这个改动会碰到谁。跨系统、跨团队、跨版本的影响，不在任何一个仓库的测试里。
- **责任**：出事谁签。补丁合进去之后线上炸了，签名的是人，不是模型。

Flash 的便宜，在这三件事上无效。它甚至让这三件事更贵：候选越多，需要签的字越多，需要留的痕越多，需要回滚的预案越多。

公告里那句「针对 Harness 做了专门优化」也在这里落位。当模型开始为框架适配，工程能力的一部分就被固化进了 harness——工具权限、验证回路、上下文管理、失败重试。**工程从「写代码」往「配 harness」挪了一格。** 这既是效率，也是新的锁定：换模型容易，换一套跑顺了的 harness 难。

## 七、从「会写」到「会筛」

对个体来说，最直接的变化是信号失效。

过去「会写」是一个粗但有效的筛选器：能独立把一个模块写完、跑通、交付的人，至少证明了他能跨过一段真实距离。现在这段距离的价格是每百万 token 几毛钱，它不再能区分任何人。

能区分人的剩下两件：**在十个候选里挑对的那个，以及说清楚为什么是它**。前者是判据，后者是可复核的推理。10-03 那篇把这叫作可验证的交付，10-14 那篇把它叫作验证设计——说法不同，指的是同一件事：证据得能被别人重跑一遍。

组织的算法也在变。一个「1 人 + N 个 agent」的编制里，N 的成本趋近于零，瓶颈落在人的审阅带宽上。理性的采购会去买审阅设施——更好的测试、更细的追踪、更快的回滚——而不是招更多初级工程师来写。这不是道德判断，是算术。

但这里必须留一句对冲：**不要把「会筛」写成新的成功学**。审阅带宽是结构给的，不是意愿给的。一个没有权限看生产日志、没有资格参加发布评审、没有时间做复盘的人，再会筛也筛不出爆炸半径。把层三的能力说成个人修养，是这一轮里最容易犯的错——它把制度问题改写成了努力问题。

## 八、三连降

把这三年连起来看，是一条很整齐的下坡：

- **第一降，code**。实现成本塌了。2026 年 1 月 Nadh 写下那句反转，说代码便宜了，给我看点说人话的东西。
- **第二降，talk**。说话的成本也在塌。设计文档、PR 描述、复盘、评审意见，便宜模型现在能写得比大部分人规整——「说清楚」的形式被批量生产，跟着一起贬值。Nadh 那句反转，用了不到一年就被下一句顶掉。

  这里要分清：便宜的是 talk 的**形式**，不是它的**内容**。把话说圆不难，知道该说什么仍然难。8-30 那篇说「说清楚最贵」，说的是内容；今天说 talk 便宜，说的是形式。形式一泛滥，内容反而更贵——因为要从一堆说得漂亮的废话里挑出说得对的那句。
- **第三降，idea**。于是有人喊 show me the idea。但想法里能被模型追平的那部分，也在塌——模型对「常见想法」的覆盖已经很好，你描述一个需求，它给出的方案往往就是行业平均值。**平均值不稀缺。**

所以准确的说法不是「idea 很贵」，而是：**能被追平的部分都在降价，降到最后只剩判断**。判断贵，不是因为它稀缺，是因为它不可外包——它连着后果。

这也是为什么「对标 Opus 5」这件事最终会变得不重要。标尺每半年抬一格，而真正决定价格的从来不是标尺，是**谁在标尺之外的地方签字**。

Flash 没有让工程变简单。它让「写」变得可丢弃，让「说」变得可批量，于是整个学科的重心被推到最后一件事上：判断什么值得做，以及做完之后敢不敢认。
